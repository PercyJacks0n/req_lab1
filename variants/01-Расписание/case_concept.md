## 1. Введение

Учебное управление университета тратит слишком много времени на формирование расписания: данные о факультетах, кафедрах, аудиториях, преподавателях, группах и учебных планах уже есть в 1С:Университет ПРОФ, но их перепечатывают заново. Из-за этого расписание появляется поздно, ошибки всплывают в первую учебную неделю, а загрузку преподавателей и аудиторий приходится считать вручную. Студенты и преподаватели ищут расписание на портале.

Наша система - это микросервис и интеграционный коннектор, который автоматически импортирует готовое расписание и справочники в формате JSON из 1С:Университет ПРОФ. Система очищает данные от дублей, сохраняет их в собственной базе и отдает пользователям через MAX-бот и веб-сервис Mini App. В отличие от текущего способа, где расписание приходится искать на портале, наше решение автоматически доставляет актуальную сетку прямо в мессенджер и браузер студента или преподавателя.

## 2. Бизнес-контекст и цели

### 2.1. Исходные данные

Сейчас расписание собирается слишком долго. 
Одни сотрудники или даже один заводят кафедры и аудитории, другие преподавателей и группы, сводят сетку занятий в таблицах. 
Данные при этом уже есть в информационных системах, но ими почти не пользуются,  итоге всё перепечатывают заново.

Из-за этого расписание появляется поздно, ошибки всплывают уже в первую учебную неделю.

Сейчас данные о расписании формируются в 1С, но до студентов и преподавателей доходят неудобным способом - через вложенные страницы портала. Кроме того, разные службы вуза могут дублировать информацию. Из-за этого возникают ошибки, а на поиск нужной пары уходит время.

### 2.2. Возможности бизнеса

Если решение появится, учебное заведение сможет собирать расписание быстрее и с меньшим числом ручных операций. Данные о факультетах, кафедрах, аудиториях, преподавателях, группах и учебных планах будут загружаться из 1С:Университет автоматически.

Учебное управление получит отчёты по загрузке преподавателей и аудиторий чтобы принимать решения: где перегруз, где простой, где нельзя поставить ещё одну пару. В итоге студенты и преподаватели получают актуальную сетку в MAX-боте или в Mini App .

### 2.4. Видение решения

Для учебного управления и студентов, система расписания в MAX - это автономный микросервис и интеграционный коннектор, который автоматически импортирует готовое расписание из 1С, очищает его от дублей и отдает в MAX-бот и веб-сервис Mini App. В отличие от текущего способа поиска файлов на портале, наше решение доставляет данные туда, где пользователь уже читает сообщения.

### 4.4. Детальный сценарий (UC-1, UC-2)

#### UC-1. Автоматический импорт готового расписания Коннектором и выдача через MAX-бот и Mini App

| Поле | Значение |
|------|----------|
| Автор / дата | Аналитик команды 2 / 2026-10-08 |
| Основное действующее лицо | Подсистема Коннектор / Студент (Преподаватель) |
| Дополнительные действующие лица | ИТ-система 1С:Университет ПРОФ, MAX Bridge API, Веб-сервис Mini App |
| Описание | Подсистема Коннектор автоматически импортирует готовое расписание в формате JSON из 1С, оптимизирует и сохраняет его внутри микросервиса, после чего MAX-бот и отдельный веб-сервис Mini App выдают эти данные пользователям по запросу. |
| Условие-триггер | Наступление времени плановой синхронизации с 1С ИЛИ входящий вебхук (Webhook) от пользователя из мессенджера MAX / HTTP-запрос от веб-сервиса Mini App. |
| Предварительные условия | PRE-1. Данные в 1С сформированы и доступны по HTTP-сервисам.<br>PRE-2. Между микросервисом, 1С и MAX настроены шифрованные каналы связи, Basic-авторизация (для 1С) и токен-авторизация (для MAX). |
| Выходные условия | POST-1. Актуальное расписание импортировано, дедуплицировано и сохранено в БД микросервиса.<br>POST-2. Пользователь получил актуальное расписание в интерфейсе MAX-бота или веб-сервиса Mini App. |
| Приоритет | Высокий (Критический функционал) |
| Бизнес-правила | BR-1. Все дублирующиеся записи из разных служб вуза при импорте сводятся к единой эталонной записи.<br>**BR-2. Аудитория не может быть занята разными группами одновременно (кроме потоковых лекций) — при обнаружении коллизии в импортированном JSON система помечает конфликт для отчёта.** |

**Нормальное направление**

1. Подсистема Коннектор по расписанию отправляет HTTP GET-запрос к сервисам 1С с заголовком `Authorization: Basic`.
2. Система 1С возвращает готовое расписание и связанные справочники в формате JSON по зашифрованному каналу.
3. Коннектор импортирует JSON, отсекает мусорные префиксы, устраняет дубликаты, проверяет данные по правилу BR-2 и сохраняет оптимизированное расписание в собственной базе данных микросервиса.
4. Коннектор при наличии изменений отправляет пакет данных через `POST /v1/bulk/events` в MAX Bridge API (с авторизацией по Bearer-токену).
5. Когда пользователь в мессенджере MAX запрашивает расписание, платформа MAX отправляет **вебхук (Webhook)** (HTTP POST-уведомление о событии) на сервер нашего MAX-бота.
6. MAX-бот мгновенно берёт сохранённое внутри микросервиса расписание и отправляет ответное сообщение пользователю в чат.
7. Если пользователь открывает **Mini App** (внутри мессенджера или как отдельный сайт в браузере), веб-сервис Mini App обращается по API к микросервису бота (с проверкой токена), получает JSON с расписанием и отрисовывает визуальную сетку занятий.

**Исключения**

- 2.0.E1. *Сервер 1С или внешний шлюз временно недоступен:* Коннектор прерывает сеанс импорта по таймауту. Ранее импортированное расписание внутри микросервиса остаётся нетронутым («гарантийно слома нет»), и MAX-бот с Mini App продолжают бесперебойно отдавать пользователям сохранённую версию.

#### UC-2. Импорт и актуализация базовых справочников из 1С:Университет ПРОФ

| Поле | Значение |
|------|----------|
| Автор / дата | Аналитик команды 2 / 2026-10-08 |
| Основное действующее лицо | Подсистема Коннектор |
| Дополнительные действующие лица | ИТ-система 1С:Университет ПРОФ |
| Описание | Автоматический импорт актуальных данных о подразделениях, аудиториях, преподавателях, группах и учебных планах из корпоративной системы 1С в базу микросервиса. |
| Условие-триггер | Запуск регламентного задания импорта в подсистеме Коннектор. |
| Предварительные условия | PRE-1. В настройках коннектора заданы URL-адреса HTTP-сервисов 1С и учётные данные для Basic-авторизации.<br>PRE-2. Сервер 1С доступен в сети. |
| Выходные условия | POST-1. Внутренняя база данных микросервиса обновлена актуальными справочниками из 1С. |
| Приоритет | Высокий (Критический функционал) |

| Бизнес-правила | BR-3. Ранее импортированные записи, задействованные в активном расписании, при исчезновении из выгрузки 1С не удаляются физически (применяется мягкая архивация), чтобы гарантировать целостность расписания в боте и Mini App. |

**Нормальное направление**

1. Подсистема Коннектор инициирует сеанс автоматического импорта.
2. Коннектор последовательно отправляет HTTP GET-запросы к эндпоинтам 1С (`Department_University`, `employees_v1`, `study_groups`, `list_curricula`).
3. Система 1С обрабатывает запросы и возвращает ответы в формате JSON.
4. Коннектор импортирует полученные файлы (отрезает служебные префиксы до первой `{` или `[`, проверяет валидность структуры JSON).
5. Микросервис обновляет данные в своей базе (сводит дубликаты, обновляет изменившиеся атрибуты).
6. Микросервис фиксирует успешное завершение импорта и количество обновлённых записей.

**Альтернативные направления**

- 2.1. *Точечный импорт дисциплин и нагрузки:* Для получения деталей учебных планов (`disciplines_departments`) коннектор берёт импортированные номера планов (`plan_number`) и выполняет отдельный GET-запрос на каждый номер плана.

**Исключения**

- 3.0.E1. *Превышение таймаута:* Система 1С не отвечает в течение установленного лимита (1800 с для тяжелых справочников, 600 с для легких). Коннектор прерывает ожидание для текущего эндпоинта и оставляет в базе микросервиса предыдущую рабочую копию данных.
- 4.0.E1. *Некорректный формат ответа:* Система 1С возвращает ответ с флагом `"error": true` или повреждённый JSON. Коннектор отбрасывает битый пакет, сохраняя целостность текущего расписания в микросервисе.

**Другая информация**

- Размер импортируемого файла может достигать 2 ГБ, а обработка в оперативной памяти ограничена 400 МБ. Коннектор использует потоковое чтение данных.

**Предположения**

- Предполагается, что ИТ-отдел вуза уведомляет об изменениях схемы JSON-выгрузок заранее.

### 4.5 Сжатые Use Cases (UC-3, UC-4)

* **UC-3: Просмотр аналитики загруженности аудиторий и преподавателей.** Сотрудник Учебного управления запрашивает отчёт. Микросервис на основе импортированного и хранимого в себе расписания автоматически рассчитывает часы нагрузки преподавателей, выявляет простои или пересечения по аудиториям (BR-2) и выдаёт готовую сводку.
* **UC-4: Взаимодействие автономного веб-сервиса Mini App с микросервисом бота.** Пользователь открывает Mini App по прямой веб-ссылке в браузере или внутри мессенджера MAX. Фронтенд Mini App отправляет запрос к API нашего микросервиса (MAX-бота), получает актуальный срез расписания и отображает его с фильтрацией по группе, преподавателю или свободным аудиториям.

## 6. Границы кейса

### 6.1. In Scope

- FE-1. Автоматический импорт готового расписания в формате JSON из корпоративной системы 1С:Университет ПРОФ.   
- FE-2. Оптимизация, очистка от дублирующихся записей разных служб и надежное хранение расписания во внутренней базе данных микросервиса Чат-бота MAX.
- FE-3. Выдача актуального расписания студентам и преподавателям по командам внутри мессенджера через Чат-бот MAX (MAX Bot).   
- FE-4. Автоматическая рассылка уведомлений пользователям в Чат-боте MAX при изменении расписания (отмены, переносы, смена аудитории или преподавателя).   
- FE-5. Разработка отдельного веб-сервиса Мини-приложения (MAX Mini App), который открывается внутри мессенджера MAX (через WebView) и доступен в веб-браузере, получая данные о расписании по API от микросервиса Чат-бота.
- FE-6. Формирование сводной аналитики и отчетов по загрузке аудиторий и преподавателей на основе хранимого расписания.

### 6.2. Out of Scope

- LI-1. Разработка автоматизированного рабочего места (АРМ) диспетчера и сеточного конструктора для ручного составления расписания (система импортирует уже сформированное расписание из внешних систем вуза).   
- LI-2. Первичный учет, ввод и редактирование справочников кадрового состава, контингента студентов, аудиторного фонда и учебных планов (ведутся во внешних системах вуза).   
- LI-3. Разработка нативных мобильных приложений под ОС iOS и Android для магазинов App Store и Google Play (клиентский доступ обеспечивается через Чат-бот MAX и веб-сервис Mini App).   
- LI-4. Учет посещаемости занятий, ведение электронных журналов успеваемости и выставление оценок.   
- LI-5. Автоматическая генерация сетки расписания с использованием алгоритмов искусственного интеллекта и нейросетей.

### 7.4. Особенности развертывания

Решение развертывается на серверах под управлением ОС Linux и состоит из двух отдельных сервисов:   
1. Микросервис Чат-бота MAX (с собственной базой данных): размещается в серверном контуре университета. Сервис автоматически подключается к HTTP-сервису 1С по зашифрованному каналу HTTPS, импортирует готовое расписание в формате JSON, очищает его от дублей и сохраняет в свою базу данных. С платформой MAX бот взаимодействует с помощью авторизации по токену (Bearer Token) и обрабатывает события пользователей через вебхуки.   
2. Отдельный веб-сервис Мини-приложения (Mini App): разворачивается как самостоятельное веб-приложение с публичным HTTPS-доступом. Внутри мессенджера MAX оно открывается во встроенном WebView-контейнере, а также может быть открыто напрямую в веб-браузере по ссылке. Сервис Mini App не хранит расписание у себя, а обращается по защищенному API к микросервису Чат-бота и получает актуальные данные. Все передаваемые данные между узлами системы зашифрованы.
